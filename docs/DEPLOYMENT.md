# Deploying RideCore

RideCore deploys as three free-tier pieces:

| Piece | Host | Address (example) |
| --- | --- | --- |
| Database | MongoDB Atlas (already in use) | `mongodb+srv://…` |
| API + Socket.IO | Render web service | `https://ridecore-api.onrender.com` |
| Web app (also installable on a phone home screen) | Vercel | `https://ridecore.vercel.app` |

Both hosts give HTTPS automatically, so phone browsers allow GPS.

## 1. Atlas: allow the API to connect

Render's free plan has no fixed outgoing IP address. In Atlas, open
**Network Access → Add IP Address → Allow access from anywhere**
(`0.0.0.0/0`). The database stays protected by its username and password.

Use a separate database name for the deployment if you want to keep
laptop test data apart, for example `…mongodb.net/ridecore-prod?…`.

## 2. Render: deploy the API

1. Sign in at render.com with GitHub and give it access to the RideCore repository.
2. **New → Blueprint**, choose the repository. Render reads `render.yaml`.
3. Fill in the two secret values it asks for:
   - `MONGODB_URI`: the Atlas connection string.
   - `CORS_ORIGIN`: the Vercel address from step 3. Until you have it, enter
     `http://localhost:8081` and change it later. Several addresses can be
     given, separated by commas.
4. Deploy. Check `https://<your-service>.onrender.com/api/health` shows
   `"database":"connected"`.

`JWT_SECRET` is generated by Render. `OTP_MOCK_DELIVERY=true` shows
verification codes in the app because no SMS provider is connected yet.

The free plan sleeps after 15 minutes without traffic. The first request
after that takes about a minute; open the health URL before a demo.

### Accounts on the deployed database

Run these once from your laptop, with `backend/.env` temporarily pointing
`MONGODB_URI` at the deployment database:

- `npm run admin:create`: create a real administrator with your own
  private email and password.
- `npm run seed:dev` (optional): add the test rider, driver and admin. It
  calls the API at `http://localhost:5050`, so run the backend locally
  against the same database while seeding. Don't use the published test
  password for accounts you keep on a public deployment.

## 3. Vercel: deploy the web app

1. Sign in at vercel.com with GitHub. **Add New → Project**, import RideCore.
2. Set **Root Directory** to `frontend`. Vercel reads `frontend/vercel.json`
   for the build command (`npx expo export --platform web`) and output
   (`dist`).
3. Add environment variables:
   - `EXPO_PUBLIC_API_URL` = `https://<your-service>.onrender.com/api`
   - `EXPO_PUBLIC_DEMO_MODE` = `false`
4. Deploy, then put the Vercel address into Render's `CORS_ORIGIN`
   (keep `http://192.168.0.131:8081` too if you still test from the
   laptop, comma-separated) and let Render redeploy.

`EXPO_PUBLIC_*` values are baked in at build time; after changing them,
redeploy on Vercel.

## 4. On the phone

Open the Vercel address in Safari or Chrome, allow location, then
**Share → Add to Home Screen**.

## Updating

Push to `master`. Render and Vercel both redeploy automatically.
